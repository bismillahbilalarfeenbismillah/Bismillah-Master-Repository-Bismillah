# SHVVP v0.5 release and re-audit dispatch packet

**Artifact.** Structural Honesty Validation Protocol (SHVVP) v0.5, a FROZEN preregistration by Bilal Syed Arfeen, freeze date 2026-07-24. It is the evaluation contract for XZ construct validation (Phase A), CVE-Bench effect control (Phase B), and seeded novel-discovery stress testing (Phase C).

**Standing of this packet, stated first because it governs how everything else may be used.**

- v0.5 is **NOT DEPOSITED** and **NOT BINDING**. It carries **no** audit verdict.
- v0.5 requires a **fresh carrying audit by two non-producer seats of different vendor families**, one GPT-class and one Gemini-class, before deposit. Both must agree; one seat cannot carry.
- **v0.1, v0.2, v0.3 and v0.4 are all HALTED.** None was ever deposited as a binding preregistration, none is binding, and none may ever be described as deposit-ready. All four ship here unmodified for lineage, with all seven carrying-seat reports and the v0.4 producer completion report.
- The **producer and editor of v0.5 are ADVISORY and NON-CARRYING**. The verifier, the audit ledger and the rule modules here are written by that same lineage: they are claims to be tested, not evidence.
- **No empirical work is claimed.** No corpus, pilot session, confirmatory session, Phase C target or result exists.
- **No inferential claim is made about the novelty routes.** Route-level statistical inference is withdrawn in full. Every route component is a descriptive, context-scoped gate. There is no route p-value, null, confidence bound, false-discovery-rate procedure, significance claim, generalization or population-level novelty claim anywhere in Section 8.

## 1. Why v0.5 exists

v0.4 was dispatched as a focused-delta re-audit. The GPT-class carrying seat returned **HALT** with three findings, two HIGH and BLOCKING. A HALT from either carrying seat blocks deposit outright, so v0.4 is HALTED irrespective of any other seat's verdict.

| Round 4 finding | v0.5 remedy | Locus |
|---|---|---|
| **F-P4-2 (HIGH, BLOCKING):** the exact binomial route test assumed cells and targets were independently allocated iid clusters sharing one success probability. The frozen design randomises sessions **within** fixed heterogeneous Phase B cells and crosses every Phase C target with both arms, and the design simulation explicitly models cell heterogeneity, so no such model is justified | **ALL route-level inference is WITHDRAWN.** Gone from the normative path: the exact binomial test, Clopper-Pearson bounds, the re-anchored nulls, the attainability record, the Class I class, family F3a, Benjamini-Hochberg over route evidence, and the labels SUPPORTED-INFERENTIAL and DESCRIPTIVE-ONLY. All eleven components are now **Class G descriptive gates**; the strongest attainable label is `SUPPORTED-DESCRIPTIVE`; cross-phase support remains conjunction-only. The producer declines to invent a superpopulation model after an audit finding | Sections 0.2, 6.8, 8.0 to 8.6; `shvvp_v0_5_route_gates.py`; A-5.1; tests T22 |
| **F-P4-1 (HIGH, BLOCKING):** the fail-closed binding was bypassable three ways, one of which returned support for R2-B with 0 of 100 passing raw items; a second constructed a derived outcome with the importable token; a third used `dataclasses.replace` to keep a genuine token while replacing evaluability | **Raw evidence is now the sole admissible input.** Every gate is recomputed inside `evaluate_gate` from mandatory raw counts. Removed: caller-supplied `hard_gate_violated`, `evaluable`, p-values, the provenance token, trusted construction, and acceptance of any derived object. `route_claims` takes only validated raw-evidence mappings and calls the evaluator itself, so replace, token and object forgery are irrelevant rather than harder. Each component freezes required fields, denominator, minimum evidence count, exact threshold and fail-closed behaviour | Sections 8.2, 8.3, 8.6; A-5.2; tests T23 |
| **F-P4-3 (MEDIUM):** deposit metadata title, description opening and intended-files list misidentified the frozen version | Every current title, description, version field and intended-file reference states v0.5; v0.1 to v0.4 references remain only where historical. Current-version parity is now tested across metadata, source, PDF, README, brief, addendum and intended files | `DEPOSIT_METADATA_v0_5.md`; verifier gate G19; A-5.3; tests T21 |

**The judgement behind this version.** Three consecutive rounds produced a producer-built route-level inferential mechanism that a carrying seat then falsified: a bootstrap that collapsed on degenerate clusters, a binding a caller could bypass, and a binomial model the frozen design does not justify. v0.5 does not attempt a fourth mechanism. It withdraws route-level inference and keeps only what the design can honestly support. Correct arithmetic under an unjustified model is still an invalid claim, and it is the more dangerous kind because it survives every check that tests only the arithmetic.

**What was NOT weakened.** The routes, their instrumentation commitments, their zero-tolerance hard gates, the near-perfect descriptive thresholds, the minimum evidence counts, conjunction-only combination and the prohibition on route substitution after unblinding all remain in force.

## 4. Known limitations of this release

1. The verifier, ledger, tests and this README are producer-built and therefore **advisory**. Four rounds have shown that producer self-verification is not a substitute for a carrying seat.
2. **Descriptive gates carry no error control.** Eleven gates on one corpus can all pass by chance, and this contract offers no error rate for that event. Section 8.5 states this and four other limits explicitly.
3. Withdrawing route inference costs the program its route-level confirmatory ambition. That cost is accepted openly rather than hidden behind a fourth attempt at a test.
4. **No simulation was re-run and no anchor research was repeated in this pass.** The receipt is carried from v0.4 and the simulation script is byte-identical apart from its version string, which the verifier proves by normalized comparison. Anchors are unchanged from v0.3, where both seats verified them against live primaries.
5. Phase B and Phase C machinery is unchanged from v0.4, which the round 4 seat verified independently, including the 256-state closure and the invalid-input behaviour.
