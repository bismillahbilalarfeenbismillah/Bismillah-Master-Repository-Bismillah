## 3. Manifest and receipt ordering, stated explicitly

The v0.4 pass produced a single fresh-extraction mismatch because the verifier receipt was written after the manifest. The order used here is fixed and was followed on every regeneration:

1. all substantive artifacts are final;
2. `verify_shvvp_v0_5.py --json verifier_receipt.json` writes the machine-readable receipt into the release;
3. this report is copied into the release;
4. `finalize_packet_v0_5.py` writes the dispatch-brief hash table **first**, then writes `SHA256SUMS` **last**, over every member except itself and excluding `__pycache__`;
5. `sha256sum -c SHA256SUMS` confirms the manifest in place;
6. only then is the archive built, and the archive is extracted and re-checked.

`SHA256SUMS` is therefore the last file written in the release directory, and it never lists itself.
