## 6. Corrected receipt history (audit-hygiene disclosure)

The OpenAI GPT-5.5 seat disclosed an audit-hygiene event and its correction. It initially ran
`python build_v05.py` in the candidate directory; the script's then-default `all` mode rebuilt
artifacts before verifying. The regenerated PDF and HTML matched the archive bytes, but the
regenerated **DOCX differed bytewise** because DOCX builds are not deterministic. The seat then
**restored `SHUDP_v0_5.docx` from the fresh archive extraction** and re-confirmed that all checked
candidate files again matched the archive bytes, and it recorded that all dispositive results are
based on the immutable archive hash and the fresh extraction, not on regenerated local output. The
seat's final internal-hash table therefore records the exact archived DOCX hash
(`394447d56b400e77e6a10263a2a5a69ddb0377473fc9c3ac3546d035f70dec39`), i.e. the corrected receipt.
This disclosure is the origin of finding F-OGPT55-01 and is the reason the build tool now defaults to
verify-only (see Section 8). The Google Gemini 3.1 Pro seat used a fresh-extraction workflow and
recorded no such event; its receipts matched the archive throughout.

## 8. Absorbed finding

**F-OGPT55-01 (LOW) -- verifier default footgun.** The build tool's default invocation ran `all`,
which regenerated PDF/HTML/DOCX before verifying; because DOCX is not byte-deterministic, an
auditor running the default against an exact extraction could inadvertently change the DOCX hash.
**Absorbed** by changing `build_v05.py` so the default action is **verify-only** and regeneration is
opt-in via an explicit `build` or `all` command, with clear usage/help and a safety notice. This
change touches only the non-instrument build tool; the four instrument files
(`SHUDP_v0_5_source.md`, `SHUDP_v0_5.pdf`, `SHUDP_v0_5.html`, `SHUDP_v0_5.docx`) are preserved
byte-for-byte. The verifier was re-run from a fresh copy after the change and confirmed the
instrument files unchanged.
