# BSSG v0.1 -- Project-Lead Exception Ledger

**Signed by:** Bilal Syed Arfeen (BayyinahEnterprise), Project Lead
**Date:** 2026-07-30
**Scope:** STILL BLOCKING items in BSSG_v0_1_DECISION_REGISTER.md §6

Under PMD v1.2 §0.4, HIGH-residual items that remain open at convergence require a
project-lead-signed exception ledger entry. This document provides those entries.

---

## GP-R4: No machine-checked antitonicity proof

**Status:** OPEN -- deferred to v0.2.
**Exception rationale:** The reference gate ships a bounded exhaustive antitonicity check
(A2: 729 contract pairs, PASS) and a bounded authority-introduction check (11110 schedules,
K=4, 10-op alphabet, PASS). GLM independently verified K=5 (19607 schedules, no violation).
These are bounded exhaustive enumerations, not unbounded proofs. A TLA+ or equivalent
formal proof is REQUIRED before freeze (spec §26 item 6) but is not required for the
DRAFT / NOT CARRIED status. The artifact's own banner and spec explicitly state this
limitation.
**Risk accepted:** A violation at K>5 or over a richer alphabet would be missed.

## GP-R8: No TLA+ model

**Status:** OPEN -- deferred to v0.2.
**Exception rationale:** Same as GP-R4. The bounded model check is the shipped verification;
the unbounded proof is a freeze prerequisite, not a carry prerequisite. Spec §26 item 6
documents this explicitly.
**Risk accepted:** Same as GP-R4.

## CL-B4: No second independent non-producer implementation

**Status:** OPEN -- deferred to post-carry.
**Exception rationale:** A second independent implementation agreeing on every frozen vector
is a freeze prerequisite (spec §26 item 6). It is not a carry prerequisite. The carrying
audit verifies the REFERENCE implementation against its own specification and test corpus;
a second implementation verifies cross-implementation consistency. These are distinct gates.
The artifact does not claim cross-implementation consistency.
**Risk accepted:** A specification ambiguity that the reference implementation resolves
one way might be resolved differently by a second implementation.

## OD-2 / OD-11: Open design decisions

**Status:** OPEN -- tracked in OPEN_DECISIONS.md.
**Exception rationale:** 12 open design decisions (OD-1 through OD-12) are documented in
OPEN_DECISIONS.md and flagged by the verifier (G10 WARN). These are design choices that
have not been frozen, not defects. The verifier correctly WARNs (does not FAIL) on them.
The DRAFT status explicitly encompasses unresolved design decisions.
**Risk accepted:** A future resolution of an open decision could require re-audit.

---

## Ledger integrity

This exception ledger is part of the carrying-audit package. Each exception is:
- Documented with explicit risk acceptance
- Bounded to v0.1 DRAFT status (exceptions do not extend to freeze or publication)
- Traceable to the specific decision-register item

No exception waives the SHVVP §0.3 two-family carry requirement. The carry is a separate
gate discharged by independent execution, not by exception.
