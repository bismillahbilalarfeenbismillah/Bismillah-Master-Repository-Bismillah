## 2. Findings (F-P8 namespace, six-part schema)

**No CRITICAL, HIGH, or MEDIUM findings. No blocking findings.**

- **F-P8-1 (LOW)**
  - *Identifier:* F-P8-1.
  - *Severity:* LOW.
  - *Locus:* `shvvp_v0_8_route_gates.py`, `route_claims` (~line 875:
    `commitment = commitments.get(cid)`) — Channel-A bundles are resolved by the
    caller-side mapping key, which is set from the raw record's `commitment_id`;
    the bundle's own top-level `commitment_id` field is then checked against the
    raw reference inside `verify_sealed_commitment` /
    `verify_realized_commitment` and the signed inner ids are checked again.
  - *Substance:* SURFACE, not substrate. A bundle whose top-level
    `commitment_id` is renamed is **rejected** when the raw record names the
    genuine signed id (check "bundle commitment_id does not match raw
    reference"), and an aliased raw id is **rejected** because the signed inner
    `commitment.commitment_id`/`pre_run.commitment_id` cannot be forged (check
    "commitment kind/id mismatch"). Observed behavior: resolution is anchored to
    the raw record's id and double-checked against two independently signed
    fields; no authentication bypass exists. The residual observation is only
    that the (unsigned) Channel-A *mapping key* is a third, non-authoritative
    copy of the identifier; the design deliberately tolerates any value there
    because both the bundle envelope and the signed payloads are cross-checked.
    This is defense-in-depth by construction, but a reader could mistake the
    mapping key for a load-bearing field.
  - *Disposition:* NON-BLOCKING. No forgery path found; all three
    identifier-copy confusion attacks (renamed bundle id, aliased raw id,
    unresolvable index) rejected in execution. Noted for rc2 documentation
    clarity only.
  - *Cross-reference:* F-P7-3 (commitment identifier auditability); dispatch
    claim "signed and resolved commitment_id"; seat tests 7g / 7g-ii; shipped
    test C1–C2.

No other findings. Specifically, nothing in the DIVERGENCE-1 sealed-anchor
