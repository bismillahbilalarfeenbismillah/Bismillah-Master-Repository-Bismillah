# BSSG v0.1 Open Design Decisions

**Status:** DRAFT / NOT CARRIED. Each decision below is UNRESOLVED at v0.1. The verifier reports WARN for unresolved decisions and does not FAIL on them; it FAILS only on package inconsistency.

Each row records the options, the source that frames the fork, the consequence of each option, and what would close the decision.

---

## OD-1. Canonical byte form for digest binding

- **Option A.** Canonicalize JSON before hashing, in the manner of RFC 8785, where "The output from JCS is a 'hashable' representation of JSON data that can be used by cryptographic methods" ([RFC 8785](https://www.rfc-editor.org/rfc/rfc8785.html)).
- **Option B.** Avoid canonicalization by signing wrapped bytes, as COSE does, which "avoids the problem of all parties needing to be able to do a common canonical encoding of the map for input to cryptographic operations" ([RFC 9052](https://www.rfc-editor.org/rfc/rfc9052.html)).
- **Consequence.** Option A requires every implementation to agree on a canonicalizer, and a canonicalization bug is a silent total failure. Option B requires byte-preserving transport and makes middlebox re-encoding fatal.
- **Current state.** The reference gate uses `BSSG-CANON-1`, an RFC 8785 style scheme that is NOT an RFC 8785 implementation. RFC 8785 is itself informational, not standards track ([RFC 8785](https://www.rfc-editor.org/rfc/rfc8785.html)).
- **Closure test.** Two independent implementations produce identical digests for the full corpus, including Unicode, large integers, and nested empty structures.

## OD-2. External monotonicity root for cross-session rollback

- **Options.** A hardware monotonic counter; a transparency-log inclusion proof; a third-party timestamp; a quorum-held highest-seen epoch.
- **Consequence.** Without one, an adversary with host access can restore an entire consistent old world, and the reference gate cannot see it because its highest-seen epochs live in process memory.
- **Precedent.** TUF enforces version monotonicity across metadata classes and aborts on any decrease ([TUF spec](https://theupdateframework.github.io/specification/latest/)).
- **Closure test.** A restore-from-backup scenario in which a stale epoch is rejected by the named root.
- **Blocking status.** Listed as STILL BLOCKING in the decision register.

## OD-3. Numeric freshness bounds per evidence type

- **Problem.** No fetched source supplies a number. RFC 9162 "deliberately does not specify any limits on the value to allow for experimentation" ([RFC 9162](https://www.rfc-editor.org/rfc/rfc9162.html)); RFC 9334 leaves the expiry threshold "defined locally to that policy" ([RFC 9334](https://www.rfc-editor.org/rfc/rfc9334.html)); CRL granularity may be "up to one hour, one day, or one week" ([RFC 5280](https://www.rfc-editor.org/rfc/rfc5280.html)).
- **Current state.** The reference gate uses a configurable default of 300 seconds for evidence age and 5 seconds for clock skew. These are placeholders with no evidentiary basis and MUST NOT be treated as recommendations.
- **Closure test.** A per-effect-class table with a stated rationale for each bound.

## OD-4. Hash and signature agility, including any post-quantum boundary

- **Problem.** v0.1 fixes SHA-256 in the digest lexical form itself, which forecloses agility at the schema level. AX-SH 5 declares "a post-quantum cryptographic boundary (hash-based integrity vs signature-based attribution)" ([AX-SH 5](https://doi.org/10.5281/zenodo.21539074)), and the witness ecosystem already points at post-quantum cosignatures ([C2SP tlog-witness](https://c2sp.org/tlog-witness)).
- **Closure test.** A digest form that names its algorithm and a migration procedure that does not invalidate historical records.

## OD-5. Reconciling an append-only log with a current-corrected-value view

- **Options.** PROV revision and invalidation graphs ([W3C PROV-DM](https://www.w3.org/TR/prov-dm/)) versus supersede-by-reissue on the same subject ([SCITT draft 13](https://www.ietf.org/archive/id/draft-ietf-scitt-architecture-13.html)).
- **Problem.** No fetched source reconciles append-only immutability with an authoritative current value, and log order is not issuance order ([SCITT draft 13](https://www.ietf.org/archive/id/draft-ietf-scitt-architecture-13.html)).
- **Closure test.** A deterministic resolution procedure that two implementations agree on for a corpus containing conflicting supersessions.

## OD-6. Strict narrowing versus non-increase plus dependent-capability removal

- **Positions.** Claude Opus 5 requires a strictly decreasing ceiling on every health decrease, otherwise the property is decorative. GPT 5.6 Sol rejects universal strictness because authority may already be empty or the degraded witness may be irrelevant, and requires global non-increase plus strict removal of every capability whose assurance dependency failed.
- **Current state.** v0.1 requires strictness only when the prior ceiling is non-empty. The irrelevant-witness case is unresolved.
- **Closure test.** A dependency-annotated capability model in which removal can be computed per witness.

## OD-7. Split or co-located decision and administration roles

- **Options.** Full PE, PA, PEP separation, or a combined service, both of which SP 800-207 permits ([NIST SP 800-207](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-207.pdf)).
- **Constraint.** Co-located roles must be re-analyzed rather than assumed safe ([RFC 9334](https://www.rfc-editor.org/rfc/rfc9334.html)).
- **Closure test.** A written emergent-risk analysis for whichever arrangement is chosen.

## OD-8. Maximum session duration and re-arming semantics

- **Problem.** The authority ratchet drives long sessions toward empty authority, and the operational workaround is an authority-widening path, which is the thing the architecture most needs to control.
- **Closure test.** A stated maximum duration plus a contract-issuance based re-arm that does not route through the adjudication path.

## OD-9. Whether evidence independence and non-bypassability may be optional at Minimal

- **Positions.** GPT 5.6 Sol: not optional, or the profile certifies a logger rather than a gate. Claude Opus 5 and Gemini 3.1 Pro: optional with mandatory disclosure, because a strict requirement makes minimal deployment impossible.
- **Current state.** v0.1 follows the disclosure route against the strongest objection in the council.
- **Closure test.** Either a Minimal profile that a real deployment can meet with independence required, or an accepted rewrite of the word conformance at that level.

## OD-10. Contract and policy as digests only, versus as normative schemas

- **Problem.** The charter fixes six schema names, none of which is a contract or policy schema, so contracts and policies enter the model only as digests plus a registry the gate consults. Three seats proposed decompositions that include a contract schema.
- **Consequence.** Contract structure, including the ceiling function per health level, is normatively undefined even though the strictness requirement of Section 9 depends on it.
- **Closure test.** Either a seventh schema in a later version or an annex that pins contract structure without adding a schema file.

## OD-11. Diagnostic richness versus regime-signal suppression

- **Problem.** BSSG deliberately preserves distinct `DENY_FALSE` and `DENY_UNKNOWN` classifications and rich reason codes, which serve auditors and also serve a probing subject seeking to infer its observation regime. Gemini 3.1 Pro named the timing and code differential as a contract-disclosure channel. This is in direct tension with PR-6 clause (b).
- **Closure test.** Either a demonstration that the subject-visible interface is identical across regimes while the auditor-visible record is rich, or an explicit admission that clause (b) is not met.
- **Blocking status.** Blocking-adjacent; listed in the decision register.

## OD-12. Witness quorum size and diversity rule

- **Problem.** No fetched source specifies a quorum size for an agency control plane. The available anchors are threshold-of-keys with unique key identity counting ([TUF spec](https://theupdateframework.github.io/specification/latest/)), the 3f+1 asynchronous replication floor ([Castro and Liskov](http://pmg.csail.mit.edu/papers/osdi99.pdf)), and the signed-message result that removes the 3m+1 floor ([Lamport, Shostak and Pease](https://lamport.azurewebsites.net/pubs/byz.pdf)).
- **Current state.** BSSG-H requires at least three witnesses under distinct administrative control, which is a producer choice with no source arbitration behind it.
- **Closure test.** A stated threshold with its independence assumption written in the same sentence.
