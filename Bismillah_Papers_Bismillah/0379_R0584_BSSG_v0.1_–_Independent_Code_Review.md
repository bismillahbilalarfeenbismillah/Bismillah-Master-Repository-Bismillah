## ***3. Code vs. Specification Review**

***I focused on Sections 20.4 (Authority Monotonicity) and 22 (Recovery and Corrections) as referenced in the code and the review instructions. I also examined the core decision logic (`authorize()` and `commit()`), the authority‑narrowing function (`\_apply\_narrowing()`), and the offline invariant checker (`check\_authority\_history()`).**

### ***Findings**

***All specified requirements are correctly implemented:**

- ***Five‑conjunct kernel – exactly the frozen set; UNKNOWN never satisfies; FALSE dominates; exhaustive truth table verified.**

- ***Caller‑supplied derived fields – structurally rejected via `PROHIBITED\_DERIVED\_FIELDS`.**

- ***Authority narrowing – `\_apply\_narrowing()` enforces that the ceiling can only shrink on health degradation; any attempted widening without an accepted amendment terminalises the session. The epoch is bumped on every change.**

- ***Witness independence – checked via `independence\_declaration` (subject\_can\_administer must be false) and `within\_auth\_assessment` (must be "outside\_subject\_authority"). The gate does not derive independence from the signature; it is an assessment.**

- ***Commit protocol – token is one‑time; compare‑and‑swap is atomic under a lock; all bindings (request\_digest, canonical\_target, params\_digest, adapter\_digest, effect\_type) are revalidated; epochs, expiry, contract revocation, and evidence freshness are checked.**

- ***Recovery (LIFT) – requires at least two adjudicators in distinct control domains, none in the subject’s domain; each signature is verified; the correction is single‑use (nonce‑like dedup).**

- ***X7 invariants – the offline `check\_authority\_history()` correctly flags:**

  - ***epoch regressions (X7)**

  - ***same‑epoch ceiling changes (X7)**

  - ***unlicensed widening (X7)**

  - ***top‑level/receipt divergence (X7)**

  - ***marker mis‑binding, replay, future‑event retro‑binding (X7)**

  - ***licensed but uncertifiable‑offline re‑widen (X7U) – in line with the V29 withdrawal (SHV Axiom 5).**

- ***Clock handling – a strict `\_read\_clock()` rejects non‑ints, negatives, and out‑of‑range values. Failures close to `DENY\_UNKNOWN` or `VOID` without coercion.**

- ***Totality / fail‑closed – all public entry points catch `BaseException` (except `KeyboardInterrupt`/`SystemExit`) and produce a recorded decision, never an escape.**

- ***Subject‑facing plane split – `subject\_facing()` collapses all denials to a constant `DENIED`, concealing the denial regime while the audit plane retains the rich classification.**

### ***No Deviations**

***The code explicitly documents its limitations (complete mediation, key custody, witness honesty, effectiveness) and does not overclaim. The implementation matches the specification’s promises.**
