## Pass B: 35th-Instance Hunt

**1. Concurrency (Locking)**
The authorize method in `bssg_gate.py` uses `with self._lock:` at line 1409. The entire authorize method, including the `_apply_narrowing` call and the ceiling writes, is serialized. There is no concurrency bug between the `contract_ceiling` empty-write (L1825) and the upgrade-write (L1847) because they both happen inside the same lock. No other state observer can read `contract_ceiling` during this window.

**2. Narrowing interaction with empty `_held`**
In `_apply_narrowing`, when `_held` is an empty Authority (`_held.effects = frozenset()`), the check `not (new_ceiling <= _held)` evaluates whether `new_ceiling.effects <= _held.effects`. If `new_ceiling.effects` is non-empty, this is `False` (e.g., `{'DELETE'} <= frozenset()` is False), so the `not` makes it `True`, and it correctly returns `"E-AUTHORITY-WIDENING"`. The check is symmetric for effects and targets. This is sound.

**3. Amendment LIFT path**
In `submit_amendment` (L2440), it reads the current ceiling at L2478: `_rc = self.state.contract_ceiling.get(session)`. It writes `restored_effects = frozenset(_rc.effects) if _rc is not None else frozenset()`. This means a lifted empty-ceiling session writes an empty grant to the ledger. This is the desired semantics—it should only be allowed to restore what was demonstrably held.

**4. Indirect Writes**
There are no other writes to `contract_ceiling`. The class fix correctly bounds the re-establishment.

**5. CE176 Execution**
CE176 executes a degraded-first scenario end-to-end. It first does a DEGRADED READ (which skips the ceiling upgrade but now writes the empty Authority), then tries a HEALTHY DELETE (which fails due to E-AUTHORITY-WIDENING), then submits an amendment, and tries a HEALTHY DELETE again (which fails due to E-AUTHORITY-WIDENING). This correctly validates the class fix.
