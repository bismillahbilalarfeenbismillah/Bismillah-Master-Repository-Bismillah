## Fixed this pass (110/110 counterexamples; 342 tests; model-check PASS; verifier 10 PASS / 1 WARN / 0 FAIL)

- **A / GPT-03 (MAJOR) + GLM-02 (MINOR) + KIMI-3 (MAJOR) -- X7 unsound and blind on real logs.**
  The X7 checker read `session_id` / `authority_snapshot` only from the top level, but real decision
  records carried neither there (both were nested in the authorization receipt), so X7 was VACUOUS on
  the gate's own logs; it also false-positived on a conformant health-only epoch bump (equal ceiling)
  and on post-accepted-amendment re-widening. Fix (structural): every decision record now carries a
  canonical top-level `session_id` / `authority_epoch` / `authority_snapshot` via `_authority_fields`;
  X7 extracts the authority triple from real records (top-level or nested-receipt fallback), licenses
  equal-or-narrowing at a higher epoch (health-only bumps), honours an accepted-amendment carve-out
  (a `bssg.correction-event` LIFT permits one re-widening), still flags epoch regression, same-epoch
  ceiling change, and un-amended widening, and flags top-level-vs-receipt `authority_snapshot`
  divergence (tampering). G11 now exercises X7 over real `gate.state.records`. (CE103.)

- **B / GLM-01 (MAJOR) + KIMI-2 (MAJOR) -- X4 blind to settlement outcomes.**
  `REDEMPTION_OUTCOMES` hand-listed a phantom `COMMITTED` (never in the execution-receipt outcome
  enum) and omitted `SUCCEEDED` (which IS in the enum and IS a completed redemption), so a
  double-`SUCCEEDED` redemption went unflagged. Fix: the redemption set is DERIVED from the schema
  outcome enum (every consuming outcome except `FAILED_NO_EFFECT`); `check_single_redemption` is a
  settlement-aware state machine so a `COMMITTED_PENDING_OUTCOME` settled once by `SUCCEEDED` is ONE
  redemption while a second commit or a second settlement on a spent token is X4. (CE104.)

- **C / GPT-02 (MAJOR) + GLM-03 (MINOR) + KIMI-4 (MEDIUM) -- reentrant refusal inherited outer conjuncts.**
  The pass-17 C3 fix passed the snapshot explicitly but left `_cur_conjuncts` ambient, so a
  pre-admission reentrant refusal recorded the OUTER call's all-TRUE conjuncts (a kernel-inconsistent
  DENY_UNKNOWN). Fix: `_authorize_abort` takes `conjuncts` EXPLICITLY; the reentrant path passes
  `conjuncts=None` -> all-UNKNOWN; no ambient read remains. (CE105.)

- **D / GPT-01 (BLOCKER, adjudicated MAJOR) + KIMI-8/9 (LOW) + GLM-04 (INFO) -- `authorized_issuance` shape-trusting.**
  The predicate checked only decision, issuance status, and token-id length, so a forged / minimal /
  schema-invalid record projected AUTHORIZED. Fix: a TOTAL, provenance-consistent predicate -- the
  record's own conjuncts must kernel-classify ALLOW, the FULL authorization receipt must validate
  against its schema, pass X8, and its conjuncts must kernel-classify ALLOW; all malformed inputs
  fail closed without raising. Added `authorized_issuance_bound()` binding the receipt digest to an
  existing UNUSED minted token. Runtime effect authorization remains enforced at commit. (CE106.)

- **E / KIMI-5 (MEDIUM) -- abort record violated the GPT-04 kernel-consistency invariant.**
  The pass-17 "preserve evaluated conjuncts" fix recorded a post-admission abort as DENY_UNKNOWN with
  all-TRUE conjuncts (`kernel_decision` -> ALLOW). Fix: a post-admission mint fault is now an
  issuance failure -- `decision = kernel_decision(conjuncts)` (ALLOW for all-TRUE) with
  `issuance_status=FAILED_NO_EFFECT` and surviving authority preserved; a pre-admission abort records
  all-UNKNOWN (DENY_UNKNOWN, also consistent). Mint faults (factory exception, malformed token) route
  through `_issuance_failure` with `E-TOKEN-MINT-FAULT` / `E-TOKEN-MINT-INVALID`. (CE107, CE99.)

- **F / GPT-05 (MAJOR) + KIMI-6 (MEDIUM) -- model-check false universal claim.**
  `st_auth` mapped every ALLOW to AUTHORIZED_UNUSED, and the "every kernel-decision record consistent"
  claim ran only on a 2-record collision fixture. Fix: every decision record carries an explicit
  `kernel_evaluated` flag; `st_auth` classifies via `authorized_issuance` (an issuance-failure ALLOW
  is not authorized); the consistency check is SCOPED to `kernel_evaluated` records and driven across
  collision, mint-abort, and nonce-replay traces. Protocol/admission denials (replay, terminal,
  structural, reentrant) are `kernel_evaluated=False` and honestly exempt; the exemption is
  demonstrated load-bearing (a replay record IS an exempted inconsistent record). (CE108.)

- **G / KIMI-1 (MAJOR) -- C7 evidence-independent expiry was asymmetric.**
  Expiry/staleness FALSE dominated on the malformed path but not the schema-valid-but-indeterminate
  path (time authority absent), so an expired request with a valid-but-time-authority-absent bundle
  was DENY_UNKNOWN. Fix: `_evidence_independent` is evaluated at the TOP of `_evidence_current`, so a
  determinate expiry/staleness FALSE dominates on EVERY path. (CE109.)

- **H / GPT-04 (MAJOR) -- clock-fault execution receipt violated its own schema.**
  `_execution_failure` wrote `commit_time_epoch_seconds = -1`, violating the schema `minimum: 0`. Fix:
  the field is now `integer|null`; a clock-unavailable fault records `null` with an explicit
  `E-CLOCK-UNAVAILABLE` reason -- schema-valid, no out-of-domain sentinel. (CE110.)

- **I / GPT-06 (MINOR) -- README stale.** "Ten-gate" -> "Eleven-gate"; the embedded exact-results
  block `MUST=87` -> `MUST=88` (regenerated from verifier output).

## Fixed this pass (102/102 counterexamples; 342 tests; model-check PASS; verifier 10 PASS / 1 WARN / 0 FAIL)

- **C1 / GPT-01 (BLOCKER) + GLM-02 + KIMI-15 -- a collision issuance-failure projected as AUTHORIZED.**
  `subject_facing()` keyed on `decision == ALLOW` alone, so a token-factory collision record
  (kernel-ALLOW, `issuance_status=FAILED_NO_EFFECT`, null receipt) projected `AUTHORIZED` with a null
  receipt. Fix: a positive `authorized_issuance()` predicate requires kernel ALLOW AND a non-failed
  issuance AND a schema-shaped, redeemable authorization receipt; every projection path derives from
  it, never from the kernel decision alone. `CE95`.
- **C7 / GPT-02 (BLOCKER) + KIMI-3 -- evidence-independent EvidenceCurrent FALSE suppressed on the
  malformed-evidence path.** An expired request was DENY_FALSE with valid evidence but DENY_UNKNOWN
  with malformed evidence, because request expiry/staleness -- knowable from the admitted request and
  the gate clock without any bundle -- were evaluated only on the full path. Fix: `_evidence_independent`
  (request expiry, staleness) parallels `_target_independent`; the malformed-evidence helper evaluates
  it and propagates any FALSE, so an independently-knowable-false request is DENY_FALSE regardless of
  evidence-bundle shape. `CE96`.
- **C4 / GPT-03 (BLOCKER) + GLM-04 -- a reentrant abort contaminated the outer snapshot.** The abort
  handler read the instance-wide `_cur_snapshot`, so a pre-admission reentrant refusal wrote the OUTER
  invocation's snapshot into `state.denied` while the outer call still ALLOWed and committed -- one
  snapshot both denied and authorized. Fix: the snapshot to terminalize is passed EXPLICITLY per
  invocation; a pre-admission reentrant refusal passes none (it admitted no request, consumed no nonce,
  terminalizes nothing); ambient context is cleared in `finally`. `CE98`.
- **C3 / GPT-04 (BLOCKER) + GLM-01 -- abort no-rollback: spec/CE/comment vs code divergence, plus an
  audit-incomplete abort record.** Spec line 172 and the CE88 label still asserted that an aborted
  authorize "rolls back partial authority/epoch state," the exact behavior GPT-02 (V14) proved unsafe;
  a spec-conformant reimplementation would reintroduce grant revival. Fix (documentation, not the
  invariant): spec line 172 rewritten to the two-shape no-rollback rule (post-admission abort preserves
  authenticated monotonic state; pre-admission reentrant refusal terminalizes nothing and consumes no
  nonce), CE88 relabeled. Additionally the post-admission abort record now preserves the evaluated
  conjuncts and the surviving authority epoch + ceiling instead of all-UNKNOWN with a null snapshot.
  `CE99`.
- **C2 / GPT-05 (MAJOR) + GLM-03 + KIMI-1 -- two amendment-rejection branches skipped the audit record.**
  The subject-domain non-independence branch and the adjudicator-signature-not-established branch
  returned directly, appending no `bssg.correction-outcome`, contradicting the pass-16 claim that every
  rejection is recorded. Fix: both route through `_amendment_reject`. `CE97`.
- **C5 / GPT-08 (MAJOR) + KIMI-2 -- X4 was unsound on real gate logs.** `check_single_redemption` flagged
  any token appearing in more than one execution record, so it false-positived on the reference gate's
  own legitimate two-`FAILED_NO_EFFECT` (zero-redemption) history. Fix: X4 counts REDEMPTIONS by outcome
  (`COMMITTED` / `COMMITTED_PENDING_OUTCOME`); a failed attempt is not a redemption. The G11 verifier
  vectors and the X4 test now exercise real-outcome vectors, not synthetic single-record dicts. `CE100`.
- **C6 / GPT-06 (MAJOR) + KIMI -- X8 tested truthiness, not an empty list.** A forged ALLOW receipt with
  `reason_codes` absent, None, 0, "" or {} passed X8. Fix: X8 requires `reason_codes` present, a list,
  and `== []`. G11 now exercises the absent case. `CE101`.
- **GPT-07 (MAJOR, vendor-unique) -- X7 missed a same-epoch ceiling change.** The subset check ran only
  when the epoch strictly increased, so a ceiling widening at a constant epoch went undetected even
  though the spec increments the epoch on every ceiling change. Fix: any same-epoch ceiling change is an
  X7 violation. `CE102`.
- **GLM-05 (MINOR) -- spec over-claimed reentrant-abort nonce consumption.** Line 172 said a reentrant
  abort "consumes its nonce"; the code (correctly) does not, since the refusal is pre-admission.
  Corrected in the line-172 rewrite (shape (2)).
- **GLM-06 (MINOR) -- dead rollback helpers.** `_snapshot_txn_state` / `_restore_txn_state` were
  unreachable after the GPT-02 (V14) no-rollback repair. Removed.
- **GPT-09 (MINOR) -- stale README test breakdown.** 243 + 4 + 92 = 339 != 342. Corrected to 95 others.
