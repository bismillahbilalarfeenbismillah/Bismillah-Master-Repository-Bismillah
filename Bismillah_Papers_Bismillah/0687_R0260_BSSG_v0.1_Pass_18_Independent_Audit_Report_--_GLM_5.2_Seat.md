### GLM-02 -- MINOR

**(2) Location:** `bssg_gate.py` lines 857-858 (`authorized_issuance`).

**(3) Claim/Observation:** The `issuance_status` check in `authorized_issuance` is `if status
is not None and status != "ISSUED": return False`. This means a record that OMITS
`issuance_status` entirely (status = None) passes this check. The docstring claims
"issuance succeeded (no FAILED_* issuance_status)" and the D repair claims a "TOTAL
predicate -- any malformed/forged record fails closed". Treating absence as passing is
inconsistent with the totality claim. In practice, this is not exploitable because a forged
record still needs a schema-valid authorization receipt (verified by `validate_record`),
and collision/issuance-failure records have `authorization_receipt = None` (caught by the
`isinstance(receipt, dict)` check). A stolen real receipt attached to a forged record without
`issuance_status` would pass the unbound `authorized_issuance` but be caught by
`authorized_issuance_bound` (provenance binding). The gate's own success records omit
`issuance_status` by design (the field is only present on failure records), so the check
works correctly for gate-produced records.

**(4) Severity:** MINOR

**(5) Evidence:**
- `bssg_gate.py` line 857-858: `status = record.get("issuance_status")` / `if status is not None and status != "ISSUED": return False`
- `bssg_gate.py` lines 1535-1548: successful ALLOW record has no `issuance_status` field
- `bssg_gate.py` line 830: failure records set `"issuance_status": "FAILED_NO_EFFECT"`
- Verified empirically: a forged record with a minimal receipt (no decision, no schema fields) fails; a forged record with a stolen real receipt but no `issuance_status` passes the unbound predicate but fails the bound predicate.

**(6) Required repair:** Either (a) require `issuance_status == "ISSUED"` explicitly (and add
`"issuance_status": "ISSUED"` to successful ALLOW records), or (b) document that the absence
semantics are intentional and the `authorized_issuance_bound` predicate is the
provenance-authoritative form. Option (a) is stronger and aligns with the totality claim.

### GLM-03 -- MINOR

**(2) Location:** `bssg_gate.py` lines 1360-1372 (`_evidence_indeterminate`), line 789
(`_deny` default `kernel_evaluated=False`), line 1337-1342 (denied-terminal path).

**(3) Claim/Observation:** The `_evidence_indeterminate` function computes
`dec, kr = kernel_decision(conjuncts)` (line 1369) and passes `decision=dec` to `_deny`
(line 1372). However, `_deny` is called WITHOUT `kernel_evaluated=True`, so the record is
marked `kernel_evaluated=False` (the default). This means the model check's
`_check_record_kernel_consistency` function (which only checks records where
`kernel_evaluated is True`) exempts these records. The records ARE currently consistent
(decision = kernel_decision(conjuncts)), but the flag creates a verification gap: if a
future code change made the decision inconsistent with the conjuncts on this path, the model
check would not catch it. The same issue affects the denied-terminal path (lines 1337-1342),
which computes `kernel_decision(all-FALSE)` = DENY_FALSE inside `_deny` but marks
`kernel_evaluated=False`.

The model check's own docstring classifies exempt records as "protocol/admission denials
(nonce replay, session terminal, structural reject, reentrant refusal)" whose "decision is a
protocol classification, not a kernel one." The evidence-indeterminate path is NOT a protocol
classification -- it IS a kernel decision over partially evaluated conjuncts (some
evidence-independent conjuncts are TRUE/FALSE, WitnessHealthy is UNKNOWN). Marking it
`kernel_evaluated=False` is a classification error relative to the model check's own
taxonomy.

**(4) Severity:** MINOR

**(5) Evidence:**
- `bssg_gate.py` line 1369: `dec, kr = kernel_decision(conjuncts)`
- `bssg_gate.py` line 1372: `return self._deny(request, conjuncts, rs, decision=dec)` -- no `kernel_evaluated=True`
- `bssg_gate.py` line 789: `kernel_evaluated: bool = False` (default)
- `bssg_gate.py` line 1467: the main deny path DOES pass `kernel_evaluated=True`
- `bssg_model_check.py` line 232: `if rec.get("kernel_evaluated") is not True: continue` -- exempts these records

**(6) Required repair:** Pass `kernel_evaluated=True` in the `_deny` call on line 1372
(since the decision IS `kernel_decision(conjuncts)`). For the denied-terminal path (lines
1337-1342), either pass `kernel_evaluated=True` (since `_deny` computes
`kernel_decision(all-FALSE)` internally) or explicitly pass
`decision=DECISION_DENY_FALSE, kernel_evaluated=True` for consistency.

## Area-by-Area Attack Summary

### Area D: authorized_issuance provenance-bound predicate

**Verdict: REPAIRED with minor residual (GLM-02).** The predicate is TOTAL (never raises --
verified by code inspection of every branch). The record's conjuncts must kernel-classify
ALLOW (exactly 5 keys, all TRUE). The FULL receipt must validate against its schema
(`validate_record` uses the custom `schema_valid` validator, which works without `jsonschema`
installed). The receipt must pass X8 (`check_allow_receipt`), and the receipt's conjuncts must
also kernel-classify ALLOW. The `authorized_issuance_bound` predicate binds the receipt digest
to an existing UNUSED minted token. I empirically confirmed that forged minimal receipts,
schema-invalid receipts, all-FALSE-conjunct records, and never-minted tokens all fail closed.
The only residual is the `issuance_status` absence gap (GLM-02), which is not practically
exploitable due to the receipt schema validation.

### Area A: X7 authority triple from REAL records

**Verdict: REPAIRED.** Every decision record now carries canonical top-level
`session_id`/`authority_epoch`/`authority_snapshot` via `_authority_fields` (line 771). The
`_authority_view` function (line 2174) extracts the authority triple from real records with
a nested-receipt fallback. The `check_authority_history` function (line 2192) correctly
handles epoch regression, same-epoch ceiling change, higher-epoch widening, health-only epoch
bumps (equal ceiling), accepted-amendment carve-out, and top-level-vs-receipt divergence.
G11 and CE103 exercise X7 over real `gate.state.records`. I verified the carry-forward logic
for deny records that omit the ceiling is sound.

### Area B: X4 settlement-aware redemption

**Verdict: REPAIRED.** `REDEMPTION_OUTCOMES` is derived from the execution-receipt schema
outcome enum minus `FAILED_NO_EFFECT` (line 2249). The `check_single_redemption` state
machine (line 2252) correctly handles: COMMITTED_PENDING_OUTCOME -> SUCCEEDED as ONE
redemption; double SUCCEEDED as X4; double COMMITTED_PENDING_OUTCOME as X4; second
settlement on a SETTLED token as X4; two FAILED_NO_EFFECT as zero redemptions. I verified
all edge cases (INDETERMINATE -> COMMITTED, QUARANTINED -> SUCCEEDED, etc.) by code
inspection. The test suite does not cover settlement outcomes (GLM-04), but CE104 and G11 do.

### Area C: reentrant refusal with explicit conjuncts

**Verdict: REPAIRED.** `_authorize_abort` takes `conjuncts` explicitly (line 1250). The
reentrant path (line 1217) passes `conjuncts=None` -> all-UNKNOWN. No ambient read remains
on the reentrant path. The except handler (line 1232-1235) reads `_cur_conjuncts` via
`getattr`, but this is set to `dict(conjuncts)` at line 1446 AFTER the kernel decision, so
it captures the actual evaluated conjuncts for post-admission aborts (not ambient state from a
previous call -- it's cleared at line 1220 and 1241). The reentrant path correctly passes
`None`, not `_cur_conjuncts`. CE105 confirms all-UNKNOWN conjuncts and kernel-consistent
DENY_UNKNOWN.

### Area F: kernel_evaluated flag and model consistency scoping

**Verdict: REPAIRED with minor residual (GLM-03).** Records carry an explicit
`kernel_evaluated` flag. The model check's `_check_record_kernel_consistency` (line 220)
scopes the consistency check to `kernel_evaluated=True` records. The `st_auth` function
(line 76) uses `authorized_issuance` (not ALLOW-to-AUTHORIZED mapping), so an issuance-failure
ALLOW is not modeled as AUTHORIZED_UNUSED. The exemption is demonstrated load-bearing (a
nonce-replay record IS exempted and IS inconsistent: DENY_FALSE vs
kernel_decision(all-UNKNOWN)=DENY_UNKNOWN). The residual is that the `_evidence_indeterminate`
path and the denied-terminal path compute kernel decisions but mark `kernel_evaluated=False`
(GLM-03).

### Area G: evidence-independent expiry at TOP of _evidence_current

**Verdict: REPAIRED.** `_evidence_current` (line 1152) calls `_evidence_independent` at the
TOP (lines 1160-1162) and returns FALSE if it's FALSE, before any evidence-dependent checks.
The `_evidence_indeterminate` function (the malformed-evidence path, line 1360) also calls
`_evidence_independent` (line 1367), so an expired request with malformed evidence is
DENY_FALSE, not DENY_UNKNOWN. CE109 confirms: an expired request with a
schema-valid-but-time-authority-absent bundle is DENY_FALSE with EvidenceCurrent=FALSE. The
fix is symmetric across both paths.
