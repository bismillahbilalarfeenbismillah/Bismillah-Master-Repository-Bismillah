# BSSG v0.1 Attack and Falsifier Register

**Status:** DRAFT / NOT CARRIED. This register is the operational companion to Sections 24 and 25 of `BSSG_v0_1_CANONICAL_SPEC_DRAFT.pplx.md`. It maps every attack to a response, a claim level, and a test, and every falsifier to the claim it refutes and the observation that would produce it.

No entry in this register asserts that BSSG stops any attack in any deployment. An entry marked ENFORCED means only that the reference gate rejects the modelled input.

## 2. Falsifier register

A falsifier is a finite observation. One occurrence makes the affected claim, profile, and boundary NONCONFORMANT. Falsifiers are not averaged away by a pass rate, and a suite that reports a percentage against them is misusing them.

| ID | Observation that would occur | Claim refuted | Where it would be seen |
|---|---|---|---|
| AF-1 | A covered effect occurs with no preceding ALLOW and no matching redemption | Non-bypassability | Effect-path audit against the decision log |
| AF-2 | One unmediated channel capable of a consequential effect is exhibited | AX-CM, and the scope of every other property | Deployment inventory review |
| AF-3 | A decision record shows ALLOW with any conjunct not TRUE | The kernel itself | Offline log check, invariant X8 |
| AF-4 | A later ceiling is not a subset of an earlier one with no interleaved accepted amendment | Bounded authority | Offline log check, invariant X7 |
| AF-5 | Two accepted inconsistent receipts for the same witness sequence and epoch with no detected conflict | Non-equivocation as detection | Cross-observer checkpoint comparison |
| AF-6 | An ALLOW exists whose witness receipt is signed by a key the subject can produce or administer | Evidence independence | Control-graph review |
| AF-7 | An UNKNOWN conjunct is resolved to TRUE by a default, retry, cache, or operator override | UNKNOWN discipline | Code review and log inspection |
| AF-8 | A lineage record claims COMPLETE while a mediated transformation is unrecorded | Provenance continuity | Invariant X6 |
| AF-9 | Any subject-visible signal distinguishes observed from unobserved operation | PR-6 clause (b) | Timing and error-code differential analysis. OPEN in v0.1 |
| AF-10 | Authority widens by any path other than an accepted independent amendment | Recovery discipline | Offline log check |
| AF-11 | A non-conformant architecture passes the conformance suite | The suite's own adequacy | Adversarial implementation exercise. UNTESTED in v0.1 |
| AF-12 | Two independent implementations disagree on a frozen vector | Conformance determinacy | Carry exercise. UNTESTED in v0.1 |
| AF-13 | A commit token is redeemed more than once | The commit protocol | Execution receipt log |
| AF-14 | An epoch lower than the highest committed value is accepted | Rollback resistance | Restore-from-backup exercise. Cross-session case OPEN, OD-2 |
| AF-15 | An unknown remote outcome is reported as proved failure or is retried automatically | Ambiguity discipline | Execution receipt outcomes |

**AF-11 is the meta-falsifier.** A conformance suite that a cheating implementation can pass launders nonconformance. The specific error to guard against, observed repeatedly in this program's lineage, is a test fixture that assumes the property under test. Two mitigations are in place at v0.1: the gate refuses caller-supplied derived facts at the structural layer, and the suite includes limitation tests whose assertions are the architecture's own failures. Neither mitigation is a substitute for an independent implementation, which does not exist.
